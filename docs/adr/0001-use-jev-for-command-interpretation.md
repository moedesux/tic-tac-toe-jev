# Use Jev for command interpretation

Replace the locally hosted Gemma/llama.cpp command interpreter with TypeSafe Jev. Jev will make bounded, typed judgments about natural-language player commands, while application code owns game rules, command execution, uncertainty policy, and deterministic response text. Qwen ASR and Kokoro TTS remain local because the change concerns semantic command interpretation, not speech processing.

## Consequences

The current repository and runtime will contain no local-SLM infrastructure or artifacts: OpenAI-compatible parsing, Gemma models and fine-tuning data, llama process management, SLM configuration and health reporting, and their tests and documentation will be removed or replaced. Structured controls will bypass inference. Natural-language control will require the remote TypeSafe service and a server-side API key; when it is unavailable, the visual game remains usable. Confidence thresholds will be calibrated against the project's command corpus, and the validated Jev model will be pinned for production reproducibility. Multi-turn clarification will use an explicit pending command containing only the known intent and missing domain value; OpenAI-style messages, tool-call records, and rolling conversation history will not be retained.

A pending command is created only for a confidently identified move that lacks a usable position. A follow-up must identify a cell; interpretation must not choose a legal or strategic move for the player. A new gameplay command replaces the pending command, while social acknowledgements leave it intact. Contextual cancellation clears it without leaving the game. Pending state has no wall-clock expiry and is cleared by completion, cancellation, replacement, a new game, game completion, or departure.

Each non-empty natural-language command will be interpreted by one batched Jev request; local phrase matching will not form a second language parser. Structured controls remain direct. FastAPI is the sole inference owner, and both browser and standalone microphone modes use `POST /api/game/command`. Its response uses domain fields such as intent, position, confidence, and clarification status rather than function-call arguments or provider response shapes. Automated tests use a fake TypeSafe boundary, while a credential-gated live suite validates the pinned Jev model. Completion also requires behavior smoke tests and a repository scan for obsolete inference artifacts.

The migration preserves the existing shared-turn game: accepted moves use the current mark and alternate X and O without caller identity or an automated opponent. Jev receives the board, turn, and game status so it can resolve uniquely identifying board-relative language, but deterministic game code remains authoritative for legality and rejects occupied or invalid cells. Games are created only by an explicit start command or structured New Game action; interpreting an unrelated command never creates one implicitly.

Commands execute one game action except for the bounded `start_game` plus initial `place_move` composition. A speculative judgment detects whether a start request also asks for an initial move, and the existing position judgments identify its cell. This exception does not introduce a general command-plan abstraction; other compound requests are clarified and handled one action at a time.

When a start-plus-move request omits or ambiguously describes its position, the game starts and the initial move becomes pending. Pending commands distinguish a missing position from a proposed position awaiting confirmation: affirmation executes the proposal, rejection requests another position, and cancellation clears it. Low-confidence follow-ups do not erase pending state. Confidence policy is risk-specific, with stricter gates for moves, existing-game resets, and position selection than for read-only or social commands; numerical thresholds are chosen from live evaluation results. The bounded compound response remains a single start intent with an optional position rather than exposing a general action list.

Command handling will be a deep asynchronous module whose small interface accepts an utterance and current game state and returns a domain command result. It hides Jev questions, confidence policy, pending transitions, response construction, and the bounded compound behavior. A command-interpreter seam has a production Jev adapter and a deterministic fake adapter for tests; SDK response types do not cross it. Command execution invokes the in-process game module rather than calling the application's own HTTP routes. The backend owns the one shared game session and pending command under the same asynchronous lock. FastAPI owns one asynchronous TypeSafe client for its application lifetime, while the standalone microphone process uses the backend command endpoint. TypeSafe credentials and the pinned model come only from `TYPESAFE_API_KEY` and `TYPESAFE_DEFAULT_MODEL`.

The old orchestration cluster is replaced rather than wrapped: the local-model orchestrator and its loopback game interface are removed, routing remains in `backend/main.py`, game rules remain in `backend/game.py`, and the standalone voice entry point receives a small backend HTTP adapter.

The migration is a hard cutover with no production fallback or dual-running flag. Generated model-training datasets and their generator are deleted; only curated, provider-neutral command fixtures remain as behavioral evidence. TypeSafe transport, credential, rate-limit, and model-availability failures use non-success HTTP statuses, while successful but uncertain judgments return a normal clarification result. Cleanup covers executable code, configuration, dependencies, scripts, tests, data, active documentation, diagrams, rendered assets, ignored model and log artifacts, and stale process files. Historical Git commits are unchanged. Retired technologies may be named only in this ADR; all operational material uses the Jev architecture.

`GET /api/health/typesafe` makes no external request. It reports whether credentials are configured and the cached outcome of actual command requests as unverified, healthy, degraded, or unavailable. A manually initiated diagnostic may list account models, but routine frontend polling consumes no TypeSafe usage.
